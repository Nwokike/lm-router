# LM Router — Final Push to v1.0.0

## What I verified before planning

- **Markdown tables have a known root cause.** `ft.Markdown.extension_set` defaults to `MarkdownExtensionSet.NONE` — literally *"Basic markdown parsing without additional extension bundle"*. Flet 1.0.1 ships `GITHUB_FLAVORED` plus table styling props (`table_head_text_style`, `table_cells_decoration`, `table_padding`). Four `ft.Markdown(...)` sites in this app never set it, so GFM tables never parse while bold/lists/links do. This is not a model problem.
- **The gateway has no auth.** The live router never verifies `Authorization`; its own console tells users `api_key="any"`. So the app must gate sharing itself.
- **The close bug is by design gone wrong.** `main.py:94` sets `prevent_close = True` and `_on_window_event` hides the window, so X never closes and there is no tray icon or visible Quit — it just looks crashed.
- **Export really is clipboard-only.** `_export_conversation` calls `_copy_text(...)`. Sherlock (`app_shell.py:394`) and DDGS (`downloader.py:78`) both use `await file_picker.save_file(dialog_title=..., file_name=...)` with a Downloads-directory fallback on mobile.
- **Our banner is already a Sherlock port**, but it diverges: Sherlock uses `adaptive_glass_bg()`/`adaptive_glass_border()`; ours uses a flat `SURFACE_CONTAINER`. Sherlock mounts it in home + history; ours only in chat + settings.
- `streamablehttp_client` is deprecated in the installed SDK in favour of `streamable_http_client` (the warning you saw — I introduced it).
- Current state: 3 direct dependencies, 112 tests green, app boots clean.

## Phase 1 — Fix what you can see

1. **Markdown tables.** Set `extension_set=ft.MarkdownExtensionSet.GITHUB_FLAVORED` on all four sites (`chat_screen.py:112`, `thinking.py:85`, `thinking.py:154`, `update_dialog.py:54`), plus `table_cells_decoration` / `table_head_text_style` so tables match the slate theme. Add a test that a real pipe-table string renders through the control.
2. **Deprecation.** Switch to `streamable_http_client`.
3. **Export writes a file.** `Export conversation` → `FilePicker.save_file(...)` with the DDGS mobile fallback to the Downloads dir, then a snackbar with the path. Keep copy-to-clipboard as the secondary action on the row.
4. **Version chip does something.** The `v0.1.0` chip becomes a button that opens the About dialog: version, build number, engine source (fetched/cached), licence links, and Check-for-updates.

## Phase 2 — Closing behaviour (your choice: both, in Settings)

5. Add `keep_running_when_closed: bool = True` to settings. X hides the window when on, closes and stops the gateway when off. Add a visible **Quit** button to the app header and Settings > Desktop, so there is always an obvious way out. The Server tab shows "running in background" when hidden.

## Phase 3 — Share your AI (auth is optional, your call)

6. **Server > Share** section: a "Require an API key" switch (default **off**), and when on a generated `sk-lm-…` key with Copy and Regenerate.
7. A small stdlib reverse proxy in front of the gateway (~80 lines, `ThreadingHTTPServer` + `urllib` forward). With the switch off it passes straight through; with it on it rejects requests whose `Authorization: Bearer …` does not match. No new dependency.
8. **Tunnel via the system `ssh`** — `ssh -R 80:localhost:4096 nokey@localhost.run`. Windows 10+, macOS and Linux all ship OpenSSH, so this is genuinely zero-dependency. `cloudflared` is ~35 MB and breaks your under-1 MB rule; `npx` needs Node. Surface the resulting `https://*.lhr.*` URL, copyable. **Desktop only** — Android has no `ssh` binary, and on mobile the honest answer is the gateway stays on the device. Failure states (no ssh, tunnel drops) get a clear message, not a hang.
